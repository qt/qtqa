# C1. C++ API reference

Back to [`skill-c-rules`](../SKILL.md).

## Purpose and style
**Purpose.** Lets a developer look up one fact about a C++ class,
function, property, enum, or macro and return to their code. The reader
arrives from search, an IDE tooltip, or a link, usually in the middle of
a task, and reads one entry, not the page.

**Style.**
- Register: reference (G23). Third person, present tense, indicative,
  one fact per sentence. The subject is the API ("Returns...", "This
  property holds...").
- Briefs: G3, G9, G10. The brief states what the entry does in one
  sentence.
- "You" only for requirements on the reader's code or choices (G4 test):
  "You must call reset() before...".
- Behavior contract: what it does, parameters (`\a`), return value,
  defaults, preconditions, thread safety, and ownership where it matters.
- No teaching, no walkthrough, no promotion. A caveat becomes a `\note`.
- Titles: noun phrase ("QString Class"), generated by QDoc.

## Node rules (C1.0-C1.10)

One rule per QDoc node type in a C1 block. Evidence: corpus survey of qt5.git `dev` at `39725828` (38,358 topic blocks), QDoc source at qttools `da04c5df8`, S3, and S4. Sub-rules are cited `C1.<n>`; they can move to their own family later.

### C1.0. Shared for all C++ API nodes
- `\brief` is for top-level nodes only (C1.1-C1.3, C1.10): QDoc shows it
  at the top of the page, in lists, index files, and the page's meta
  description. Members (C1.4-C1.9) need no `\brief` (R14). Where a brief is
  present, it ends with a period (R15; QDoc warns in HTML only). [tool]
- `\since`: the later of the first tag that contains the API and the
  module's first public release. A member inherits its class's `\since`
  and adds its own only when git shows it is newer. [tool: git]
- Don't write text QDoc generates: access-function and notifier lists,
  "This property supports QProperty bindings", `\since` sentences, overload
  notes, the Q_INVOKABLE note. [LLM]
- Warning "No output generated for X because Y is undocumented": document
  the aggregate Y (C1.1), not X (route in `tools/qdoc-fix/warning-routes.tsv`).

### C1.1. Class, struct, union
- `\brief` "The X class provides|is|contains|specifies ..." (S3; QDoc
  manual; 1,761 of 2,589 class briefs). Struct: "The X struct ...". [tool]
- Required: `\brief`, `\inmodule` (QDoc warns), `\since` (S3). [tool]
- Class docs in the `.cpp` file (S3). [tool]
- The detailed description doesn't repeat the brief (QDoc manual). [LLM]

### C1.2. Namespace
- `\brief` "The X namespace contains|provides ..." (corpus). `\inmodule`
  (QDoc warns). [tool]

### C1.3. Header file
- `\brief` "The <x.h> header file provides|declares ..." (corpus).
  `\inmodule` (95%). [tool]

### C1.4. Function (`\fn`)
- No `\brief` (99% of 13,779). The first sentence starts with the verb for
  the function kind (S3). [tool: opener; LLM: fit]

  | Kind | Opener | Evidence |
  |------|--------|----------|
  | constructor | Constructs | S3; 591 of 921 |
  | copy or move constructor | Copy-constructs, Move-constructs | corpus; QDoc default text |
  | destructor | Destroys | S3; 88 of 122 |
  | getter | Returns | S3; 2,346 |
  | bool | Returns \c true if ...; otherwise returns \c false. | 560 of 944; QDoc return check |
  | setter | Sets | 691 of 1,004 |
  | signal | This signal is emitted when (preferred; S3 also lists Triggered when, Emitted when) | 1,269 |
  | slot, notifier | when it runs ("This slot is executed when") | S3 |
  | assignment operator | Copy-assigns, Move-assigns | corpus; QDoc default text |
  | comparison operator | Returns \c true if | 595 |

- `\a` for every parameter (QDoc warns; not needed for overloads and
  reimplementations). [tool: QDoc]
- `\overload` on overloads. Non-member functions: `\relates` (68%). [tool]
- Preconditions, behavior, and consequences (S3 "must include"). [LLM]
- Undocumented trivial special members are optional: QDoc generates
  "Destroys the instance of X." and similar text. [LLM]
- Replaces G9 for C++.

### C1.5. Property (`\property`)
- No `\brief` needed: a member brief isn't used in lists or summaries; it
  renders as the first paragraph of the property's entry (R14). Start the
  body with "This property holds ..." (S3; QDoc manual examples). [tool]
- Existing `\brief` in property blocks (2,378 blocks) is a legacy form:
  QDoc renders a brief starting with The, A, An, Whether, or Which as "This
  property holds ...". Don't flag it; don't add new ones. Never write
  `\brief This property holds ...`: WebXML output renders it as "This
  property holds this property holds ..." (74 blocks). [tool]
- `\c` for values, ranges, and defaults (S3). [LLM]
- Replaces G10 for C++ properties.

### C1.6. Variable (`\variable`)
- Same as C1.5: no `\brief` needed; body starts "This variable holds
  ...". Legacy briefs render with the same rewrite. [tool]

### C1.7. Enum (`\enum`)
- No `\brief` (97%). Body starts "This enum describes|specifies|..."
  (corpus). [tool: opener; LLM]
- `\value` for every item; `\omitvalue` for hidden items (S3; QDoc
  warns). [tool: QDoc]

### C1.8. Typedef and type alias
- One sentence naming the aliased type: "Synonym for X." or "Alias for X."
  Use one form per module (corpus is split). [LLM]
- Non-member: `\relates`. [tool]

### C1.9. Macro
- `\relates` to its header or class (96%). [tool]
- Opener "This macro ..." or, for feature macros, "Defined if ...". `\a` for
  macro parameters. [LLM]

### C1.10. Concept (`\concept`, QDoc 6.13)
- `\brief` noun phrase ("A type that admits a total order.", QDoc manual).
  `\inmodule` on the concept; constrained items need nothing (manual). [tool]

## Exemptions
G4 ("you") doesn't apply to briefs.

## Gaps
- `\a` for every parameter (QDoc: `Undocumented parameter`)
- `\value` or `\omitvalue` for every enum item
- `\since` equals the upcoming release; no backdating
- `\brief` is one sentence followed by a blank line
- Constructors start "Constructs", destructors "Destroys"
- Class docs live in the `.cpp` file, not the header
- Behavior contract: preconditions, behavior, defaults (G)

## Sample

A minimal passing sample of this type:

```qdoc
/*!
    \class QFooRange
    \inmodule QtCore
    \since 6.12
    \brief The QFooRange class stores a numeric range.

    Use QFooRange to clamp values between a minimum and a maximum.
*/

/*!
    Returns the lower bound of the range.

    \sa setMinimum()
*/
```
