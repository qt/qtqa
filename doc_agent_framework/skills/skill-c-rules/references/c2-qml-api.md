# C2. QML API reference

Back to [`skill-c-rules`](../SKILL.md).

## Purpose and style
**Purpose.** Lets a developer look up a QML type, property, method, or
signal while writing QML. The reader often comes from Qt Creator's
context help or completion.

**Style.**
- Register: reference (G23). Same voice as C1: third person, present
  tense, one fact per sentence.
- Briefs: "This property holds...", "This signal is emitted when..."
  (G10). State the property type, default, and whether it's read-only.
- Link to QML targets, not C++ classes (G16), except for backing types
  named with `\nativetype`.
- Short QML snippets are welcome; they show usage, not a tutorial.
- Titles: "<Type> QML Type", generated by QDoc.

## Node rules (C2.0-C2.5)

One rule per QDoc node type in a C2 block. Evidence: corpus survey of qt5.git `dev` at `39725828` (38,358 topic blocks), QDoc source at qttools `da04c5df8`, S3, and S4. Sub-rules are cited `C2.<n>`; they can move to their own family later.

### C2.0. Shared for all QML API nodes
- C1.0 applies (`\brief` only on top-level nodes, `\since`, no generated
  text). The QML type (C2.1) needs a `\brief`: QDoc shows it in lists and
  the meta description, not on the type's own page. QML members (C2.2-C2.5)
  need none.
- Don't write the signal handler name or `[read-only]` for C++-backed
  properties: QDoc adds "The corresponding handler is onX." and derives
  read-only from the C++ property. [LLM]

### C2.1. QML type and value type
- `\brief` works in a list: QDoc hides it on the type's own page. "Provides
  ..." or a noun phrase (S4 allows both). [LLM]
- Required: `\inqmlmodule` (100%), `\since` (S4). [tool]
- C++-backed: `\nativetype` (S4; QDoc doesn't check it). A C++ class with
  `QML_NAMED_ELEMENT` needs both `\class` (C1.1) and `\qmltype`, with the
  same `\since`. [tool: header scan]
- `\inherits` for the public inheritance chain (S4). [tool]
- Uncreatable types (`QML_UNCREATABLE`) get no note (module convention; no
  source). [LLM]

### C2.2. QML property and attached property
- Type after `\qmlproperty` (S4; QDoc warns "Invalid QML property type").
  [tool]
- No `\brief` (98%). The body starts "This property holds ..." (1,584):
  QDoc doesn't rewrite QML briefs. Attached: "This attached property holds
  ...". [tool]
- `\readonly` when the property isn't C++-backed or the backing property is
  writable (S4; QDoc derives the rest). `\default`, `\required` where they
  apply. [LLM]
- Replaces G10 for QML properties.

### C2.3. QML signal and attached signal
- "This signal is emitted when ..." (891 of 971). [tool]
- `\a` for parameters (S4: say whether the signal accepts a parameter).
  [tool]
- S4's "mention the corresponding signal handler" is met by QDoc's
  generated line; don't repeat it. [LLM]

### C2.4. QML method and attached method
- Verb opener (S4: Changes, Updates, Returns, Called). [LLM]
- `\a` for parameters; the return value in `\c` (S4). [tool, LLM]
- Replaces G9 for QML.

### C2.5. QML enumeration
- `\qmlproperty enumeration` or `\qmlenum`, with `\value` for each value,
  or `\qmlenumeratorsfrom` to copy a C++ enum (S4). [tool]

## Exemptions
G4 doesn't apply to briefs.

## Gaps
- `\qmlproperty` states the type
- `\qmltype` has `\inqmlmodule`; `\nativetype` for C++-backed types
- `\readonly` for read-only properties
- `\value` for each `\qmlproperty enumeration` value
- Each signal names its handler and parameters (G)

## Sample

A minimal passing sample of this type:

```qdoc
/*!
    \qmltype Gauge
    \inqmlmodule QtFoo
    \nativetype QFooGauge
    \since 6.12
    \brief Shows a value on a dial.
*/

/*!
    \qmlproperty real Gauge::value

    This property holds the current value. The default is \c 0.
*/
```
